一页摘要

  • 给谁用：投诉处理岗、质检员、质检主管 / 合规岗、消保管理岗四类用户。
  • 解决什么：投诉质检靠人工抽检（示例：约 5%），口径因人而异；高风险投诉靠经验识别，发现得晚；处置依据靠翻制度、问老员工。
  • 产品怎么做：机器做全量初筛、分类和一致性判断，人做高风险定性和最终裁决。规则类评分点可复算，语义类评分点必须给出证据片段；命中高风险或置信度低的，一律转人工。
  • MVP 范围：选 1 类高频投诉，做通“结案 → 自动质检 → 分流 → 人工复核 → 改判回流”这一条闭环，外加接入时的高风险标记（P0）。知识库助手、整改闭环放 V1，聚集预警和驾驶舱下钻放 V2。
  • 怎么判断做对了：分类准确率 ≥ 90%、高风险召回率 ≥ 95%、质检一致性 ≥ 85%（均为示例门槛），同时盯漏检率和改判率；达不到就不扩大范围。

1. 背景与产品目标

1.1 背景

银行保险机构消费者权益保护监管持续趋严，投诉处理已从“服务问题”升级为“合规问题”：

  • 时效硬约束：监管对投诉受理、处理、回复有时限要求（具体以适用的监管与行内制度为准），逾期会影响消保监管评价；
  • 征信类投诉敏感度极高：征信异议类投诉处理出错，可能引发监管转办和声誉风险；
  • 量在涨，人没涨：投诉量随业务量增长，处理和质检人力无法同比扩张；
  • 检查看过程：监管与内审不只看结果，还看过程留痕（录音、话术、时效），质检本身就是证据链的一环。

1.2 产品目标

  1. 质检覆盖从人工抽样约 5%（示例）变为全量机器初筛 + 高风险人工复核；
  2. 建立统一、可解释、可申诉的评分点体系，每个评分点能追溯到法规与行内制度条款；
  3. 投诉接入时自动分类分级，高风险投诉分钟级识别、优先派单；
  4. 把法规制度和历史复杂案件沉淀为可检索、带出处的知识库，缩短新人上手周期。

1.3 不做什么

  • 不做无人化：重大问题定性、客户最终回复、结案结论，系统只给建议，不自动执行；
  • 不替换现有工单、录音系统，只读接入；
  • MVP 不做排名通报：先用于辅导和风险拦截，避免一线把它当“找茬工具”。

3. 核心流程与产品架构

3.1 设计原则

  1. 人机协同，不承诺无人化：机器负责全量初筛、分类、评分与预警；定性裁量、客户沟通、最终结案保留人工确认；
  2. 合规优先于效率：模型输出必须可解释、可溯源、可审计，评分依据锚定条款原文，不接受“模型觉得”；
  3. 宁可多转人工，不可漏高风险：阈值先从保守开始，用复核数据逐步收紧；
  4. 小步验证：新评分点先影子运行（只评分、不生效），和人工结果比对达标后再启用。

4. 功能清单与优先级

4.1 怎么排优先级

  • P0 = 没有它闭环跑不通，或者漏了会出合规事故。MVP 只做一类高频投诉的“结案质检闭环”，再加接入时的高风险标记：高风险漏判的代价最大，必须第一版就有。
  • P1 = 提效明显、但缺了不影响闭环。知识库和整改任务依赖 P0 积累的数据（改判记录、问题清单），放第二版效果更好。
  • P2 = 管理层面的增强。数据量起来、评分点稳定之后再做才有意义。

5. 功能设计

5.1 工单分类分级

  • 按现行分类体系（业务类型 × 诉求类型 × 风险等级）打标；征信类诉求可按诉求性质继续细分；
  • 多诉点工单允许多标签，按最高风险诉点定级；
  • 涉征信异议、涉监管转办、涉媒体 / 诉讼 / 群体性风险的，专项标记并优先派单；
  • 每个分类结果带置信度，低置信度转人工确认，不硬分错派。

5.2 智能质检引擎（核心）

把质检标准从“打分表”变成“可执行的评分点”，每个评分点四要素齐全：检查对象、判定规则、证据来源、定性标准。示例（全表见附录 A）：

评分点检查对象判定方式定性
时效合规工单时间戳 vs 监管 / 行内时限规则引擎精确计算超时即重大问题
身份核验录音转写文本语义识别是否完成规定核验动作缺失即合规问题
法规告知完整性回复话术 / 书面回复与制度要求的话术要素逐项比对要素缺失按项扣分
处理结论与诉求匹配工单结论 vs 客户诉求语义判断，低置信度转人工不匹配进入复核队列
证据链完整性归档材料清单规则校验必备材料是否齐全缺件自动退回补正

设计要点：规则类评分点用规则引擎（结果确定、可复算），语义类评分点用大模型（给判断必须给证据片段）。两类结果在页面上分开显示，质检员可以逐项改判，改判全量留痕。这是评分体系能被一线接受、经得起申诉的前提。

5.3 RAG 知识库处置助手

  • 知识范围：消保相关法规与监管文件、行内投诉处理制度与话术规范、脱敏后的历史复杂案件；
  • 回答强制带引用：每条建议标注来源文件与条款，查不到就回答“未检索到依据”，不编造；
  • 按案件类型预置核查清单（如征信异议类案件需要核查哪些记录、各查什么），新人按清单执行即可达到合规底线；
  • 知识库按版本管理：法规更新后旧条款标记失效，引用到失效条款的回答会提示。

5.4 风险预警

  • 升级预警：客户明确提到监管投诉、媒体曝光、法律途径等，实时标记；
  • 时效预警：临近处理时限未结案的工单分级提醒，避免“忘了”造成合规事故；
  • 聚集预警（V2）：同一产品、渠道、合作机构的投诉量短期异常上升，自动生成简报。

5.5 管理驾驶舱

质检覆盖率、问题类型分布、团队与个人质量趋势、整改完成率、投诉分类分布，全部由质检结果自动生成，替代人工 Excel 汇总；V2 支持按机构、团队、产品、渠道下钻。

7. 评测指标与人工复核机制

7.1 评测指标

指标口径示例门槛在哪测、多久看
分类准确率自动分类与人工金标准一致的工单数 ÷ 测试集工单数；业务类型和诉求类型两级都对才算对≥ 90%上线前历史标注集回测；上线后月度抽检 + 处理岗改类记录
高风险召回率被正确标为高风险的工单数 ÷ 金标准中全部高风险工单数≥ 95%专项测试集；宁可误报不可漏报

转人工率进入人工复核队列的工单数 ÷ 结案工单数15%–25%（示例）日度；要和质检人力匹配
引用准确率知识库回答中引用条款真实且适用的比例≥ 95%月度抽样人工核验

取舍：高风险召回率和转人工率是一对矛盾。阈值调低，召回升高，转人工率也跟着升高，复核人力扛不住。上线初期先保召回，接受较高的转人工率；再用改判数据看哪些转人工是“白转”，逐步收紧阈值。

7.2 哪些情况必须转人工

#触发条件例子为什么
1命中高风险标签，不论置信度涉征信异议、监管转办、媒体 / 诉讼 / 群体性漏判代价最大，必须人看
2任一重大评分点判为问题或疑似时效超时、身份核验缺失、结论与诉求不匹配重大问题会进通报和整改，定性必须由人做
3置信度低于阈值分类或语义评分低于 0.8（示例）模型自己都拿不准
4规则结果与语义结果冲突，或给不出证据片段规则判通过、语义判有问题；判了问题但定位不到原话没有证据的判断视为无效
5一线申诉被质检人不认可结果由非原质检员复核，保证公平
6自动归档件随机抽查低风险自动归档件抽 5%（示例）唯一能量出漏检率的口子，防止机器盲区
7评分点处于影子运行期新上线或刚修订的评分点只评分不生效，与人工双轨比对

7.3 复核结论怎么回流

改判原因流向谁处理
模型误判进入校准样本集，定期重新评测模型 / 算法
评分点标准不清该评分点进入修订待办，必要时退回影子运行质检主管
证据不足（转写错误、录音缺失）记为数据问题，按渠道统计数据 / 系统
特殊情形沉淀为判例，进入知识库质检主管

这和人工质检时“先归因再解决”是一个思路：同样是判错，是模型问题、标准问题还是数据问题，处理办法完全不同。

7.4 防幻觉设计

  1. 引用溯源强制开启：知识问答和质检判定中，每条法规类结论必须挂原文出处，无出处不输出；
  2. 置信度分流：低置信度结果不自动生效，界面明示“需人工确认”；
  3. 人审兜底：重大问题定性、客户最终回复、结案结论三类动作，系统只给建议；
  4. 灰度与回滚：新评分点先影子运行，异常可一键回滚到上一版本。

9. 数据安全与风险

9.1 数据安全

  • 私有化部署：模型、向量库和业务数据部署在行内环境，数据不出域；
  • 脱敏：客户姓名、证件号、卡号等进入模型前自动脱敏，按权限还原；
  • 权限分级：按岗位设定可见范围，与行内现有权限体系对齐；
  • 审计日志：谁在什么时间查了什么、改了什么评分，全量留痕。

附录 B：几个产品取舍

  • 为什么不让机器直接出最终结论？质检结果会进通报、影响一线考核，一旦误判，伤的是整个体系的公信力。所以重大问题必须人定性，机器的价值是把人的注意力集中到该看的地方。
  • 为什么 MVP 不做全量分类，却要做高风险标记？普通分类分错了，处理岗改一下就行；高风险漏掉了，可能就是监管转办。先做代价最大的那一块。
  • 为什么要随机抽查“机器判没问题”的件？只复核机器报出来的问题，永远量不出机器漏了什么。抽查是漏检率唯一的数据来源。
  • 为什么改判必须选原因？不选原因，改判数据只能说明“机器错了”，说明不了该改模型、改标准还是修数据。
