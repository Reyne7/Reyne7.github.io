## 作品一：贷前人工审核质检看板

**背景**：银行贷前审核中，少数件会流转到人工审核，再由质检员抽检。现状痛点：

1. 分层抽样规则是静态的，只看“件”的特征，不看审核员个人的异常；
2. 质检员尺度不一；
3. 质检结果约一周后才以分组宣导的形式反馈；
4. 宣导之后同类差错有没有减少，没人追踪。

看板演示解决方案中的**一致性看板**、**闭环追踪**与**AI 辅助质检**，分四个页面，每页顶部用一句话给出本页结论：

| 页面 | 结论与内容 |
|---|---|
| 团队总览 | 质检结果平均约 7 天才反馈到审核员，宣导后差错率明显下降。主卡片为反馈时效，辅以件量、覆盖率、差错率及环比；月末异常预警；8 周差错率趋势（周度明细可展开） |
| 审核员画像 | 异常审核员的月末通过率明显高于平时，而现有抽样只抽到其月末件的不到两成。审核员表按月末偏移排序；点开看周趋势、逐日通过率与件列表；质检员尺度以“偏离团队均值”条形图对比 |
| 宣导效果追踪 | 宣导后“政策理解偏差”明显下降，另外两类差错没有变化。三类差错 8 周发生率曲线、宣导前后显著性检验、宣导记录 |
| AI 辅助质检 | AI 标出的疑似问题中，质检员确认了绝大部分，异常审核员月末备注全部因理由不充分被标出。10 条模拟备注，逐条展示 AI 标出的问题片段、判断与差错类型、推荐判例和质检员最终结论（含 1 条被驳回的 AI 误判） |

**模拟数据**：在浏览器中用固定随机种子生成 12 名审核员、3 名质检员、最近 8 周约 4,600 件人工审核件，每次打开结果一致。数据中埋了两个故事：

- 审核员 R07 在每月最后 5 天通过率、与模型分歧率明显升高，审核时长明显缩短（对应“为 KPI 动作变形”）；R08 月末通过率也偏高，但没有其他信号佐证，标为“需关注”；
- 第 4 周（9 月 2 日）针对“政策理解偏差”做了一次宣导，之后这类差错率明显下降，另外两类没有变化。

**AI 辅助质检的实现方式**：网站是公开静态页面，不能在前端调用大模型接口（会暴露密钥）。因此 10 条模拟备注的标注结果（问题片段、问题类型、建议差错类型、理由、推荐判例）由大模型预先生成，保存在 `qc-dashboard/ai-review.json`，页面只读取展示；质检员最终结论和被驳回的 AI 误判也是数据的一部分。页面上的“节省阅读时间”是按假设值估算的，非实测。

> 所有数据均为模拟生成，不代表任何真实机构。

## 如何在 GitHub Pages 上打开

1. 进入仓库 **Settings → Pages**；
2. **Build and deployment** 中 Source 选择 **Deploy from a branch**，Branch 选择 `main`、目录选择 `/ (root)`，保存；
3. 约 1 分钟后访问：
   - 首页：<https://reyne7.github.io/>
   - 看板：<https://reyne7.github.io/qc-dashboard/>

仓库名为 `用户名.github.io` 时，GitHub Pages 通常会自动启用，合并到 `main` 后即可访问。

## 本地预览

在仓库根目录运行：

```bash
python3 -m http.server 8000
```

然后访问 <http://localhost:8000/>。前三个页面直接双击 `index.html` 也能打开，但“AI 辅助质检”页需要读取 `ai-review.json`，浏览器会禁止从本地文件读取，所以请用上面的方式预览。图表使用 Chart.js（通过 cdnjs CDN 引入），需联网加载；断网时表格数据仍可正常显示。
