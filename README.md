## 信贷审批策略分析

基于 Kaggle 公开数据集 Give Me Some Credit（15 万名借款人）：数据清洗、IV、规则命中与增量、WOE 评分卡、收益驱动的 cutoff、swap set，附可交互的策略模拟器。分析代码见 https://github.com/Reyne7/credit-risk-strategy-simulation 。

## 审批决策引擎 PRD

让策略人员自助配置规则与分数线，先回溯测算、再审批、用冠军挑战者灰度上线。“回溯测算”原型中的数字来自上面的策略分析。

## 贷前人工审核质检看板

**背景**：信贷审核的人工质检常见做法是按周批量处理：批次结束后抽样、集中质检、汇总公布结果，再通过宣导会讲共性问题。一件审核件从审完到征信员知道自己错了，往往要一周以上。

**产品目标**：质检结论次日送达征信员本人。审核完成即进入质检池 → 当晚 AI 全量初筛 → 次日质检员复核疑似件和抽检件 → 结论推送到本人，争议线上处理。

| 页面 | 内容 |
|---|---|
| 闭环总览 | 上线前（W5–W8）与上线后（W9–W12）对比：4 个 KPI 卡（反馈时效、人工复核覆盖、月末异常发现用时、差错率）；反馈链路甘特图（示意）；质检覆盖圆环；12 周反馈时效与差错率、差错类型堆叠柱；上线效果检验（双比例 z 检验与所需样本量）；征信员 × 日期月末热力图；指标谁用、口径与局限 |
| 征信员画像 | 上线前诊断：月末偏移排序、个人周趋势与逐日通过率、质检员尺度对比 |
| 宣导效果追踪 | 上线前诊断：三类差错宣导前后对比与显著性检验 |
| AI 辅助质检 | 10 条模拟备注的 AI 标注、关联信号、推荐判例与质检员最终结论 |

**模拟数据**：浏览器中用固定随机种子生成，每次打开结果一致。W1–W8 为上线前（12 名征信员、约 4,600 件），W9–W12 为上线后（约 2,300 件，前 8 周数据不受影响）。上线后数据基于三个假设：征信员收到本人某类差错反馈后，该类差错倾向降为原来的 35%；AI 对有差错件的召回为 88%、对无差错件误标 6%；月末异常被反馈后组长当天介入。差错率在 4 周内下降但尚不显著，看板如实展示，并给出检出所需的样本量。

**AI 辅助质检的实现方式**：网站是公开静态页面，不能在前端调用大模型接口（会暴露密钥）。因此 10 条模拟备注的标注结果由大模型预先生成，保存在 `qc-dashboard/ai-review.json`，页面只读取展示。

> 所有数据均为模拟生成，不代表任何真实机构。

## 如何在 GitHub Pages 上打开

1. 进入仓库 **Settings → Pages**；
2. **Build and deployment** 中 Source 选择 **Deploy from a branch**，Branch 选择 `main`、目录选择 `/ (root)`，保存；
3. 约 1 分钟后访问：
   - 首页：<https://reyne7.github.io/>
   - 看板：<https://reyne7.github.io/qc-dashboard/>

仓库名为 `用户名.github.io` 时，GitHub Pages 通常会自动启用，合并到 `main` 后即可访问。

## 本地预览

在仓库根目录运行：

```bash
python3 -m http.server 8000
```

然后访问 <http://localhost:8000/>。前三个页面直接双击 `index.html` 也能打开，但“AI 辅助质检”页需要读取 `ai-review.json`，浏览器会禁止从本地文件读取，所以请用上面的方式预览。图表使用 Chart.js（通过 cdnjs CDN 引入），需联网加载；断网时表格数据仍可正常显示。
